# Подключение к языковой модели

Используйте `google/gemma-4-31B-it` через API организаторов. Отдельный сервер для модели и локальная загрузка весов не нужны. API совместим с описанным ниже подмножеством Chat Completions.

За получением ключа доступа обращайтесь к [@ynwaks](https://t.me/ynwaks) в Telegram. Рабочий ключ каждой команды организатор передаёт лично. В этом репозитории рабочих ключей нет. Значения из `.env.example` служат образцом настройки.

## Подключение и срок

| Переменная | Значение |
|---|---|
| `LLM_BASE_URL` | `https://sfedu-hackathon-ai-gateway.sfedu-hackathon-ai-gateway.workers.dev/v1` |
| `LLM_MODEL` | `google/gemma-4-31B-it` |
| `LLM_API_KEY` | Индивидуальный ключ, полученный от организатора |
| `LLM_USER_AGENT` | Имя клиента команды, например `hackathon-team-01/1.0` |

Командные доступы действуют до **22 ноября 2026 года, 19:00 по Таганрогу / 17:00 по Мадриду / 16:00 UTC**. За настройками и индивидуальным доступом обращайтесь к организатору. В финальной проверке передаются параметры организатора через те же переменные; не фиксируйте ключ или адрес в коде.

## Ограничения одного вызова

| Параметр | Требование |
|---|---|
| Модель | Только `google/gemma-4-31B-it` |
| Сообщения | От 1 до 40, только текст; роли `system`, `user`, `assistant` |
| Тексты сообщений | Суммарно до **32 768 байт UTF-8**: инструкции, история и переданные данные вместе |
| Полный JSON-запрос | До **65 536 байт UTF-8** |
| Выход | Целое число от 1 до **2 000 токенов**, по умолчанию 1 000 |
| Формат ответа | Обязателен `json_object` или `json_schema` с `strict: true` |
| Размер JSON-схемы | До 16 384 байт в компактной JSON-записи, до 128 узлов, глубина до 12 |
| Параллельность | До **2 одновременных вызовов** на команду |
| Частота | До **20 попыток генерации за скользящие 60 секунд** на команду |
| Ожидание модели | До 90 секунд на один вызов; общий запуск `run` по контракту — до 120 секунд |

Вход ограничен в байтах, выход — в токенах модели. Для проверки размера текста на Python используйте `len(text.encode("utf-8"))`; количество символов не равно количеству байт или токенов. JSON и содержащаяся в нём схема также входят в общий размер HTTP-запроса.

Укажите `max_tokens` **или** `max_completion_tokens`; передавать оба поля нельзя. Потолок выхода не означает, что ответ обязательно будет такой длины. Для короткого извлечения условий обычно достаточно 128–256 токенов, для вариантов с объяснениями — 512–1 000.

Рассуждения отключены на стороне API. Допускаются только `stream: false` и `n: 1`. Инструменты, изображения, аудио и прочие неизвестные поля запрещены. `temperature` можно задавать в диапазоне 0–2, `top_p` — 0–1. Включать `reasoning` нельзя; при явной передаче допустимы только `reasoning: {"enabled": false}` и `reasoning_effort: "none"`.

Частота учитывает принятые попытки обращения к модели, включая её ошибки. Некорректные запросы, отклонённые до генерации, эту квоту не расходуют. Лимиты и статистика команды сохраняются при перезапусках шлюза. Общий доступ индивидуален; если он недоступен, обратитесь к организатору.

## Запрос

`POST {LLM_BASE_URL}/chat/completions`

Заголовки:

```text
Authorization: Bearer <индивидуальный ключ>
Content-Type: application/json
User-Agent: hackathon-team-01/1.0
```

У сообщения ровно два поля: `role` и `content`. Полный пример находится в [llm/request.example.json](llm/request.example.json). Минимальная форма:

```json
{
  "model": "google/gemma-4-31B-it",
  "messages": [
    {"role": "system", "content": "Извлеки условия покупки. Верни только JSON."},
    {"role": "user", "content": "Стол не шире метра, кресло и лампа. Таганрог. До 15 000 ₽ за всё."}
  ],
  "max_tokens": 256,
  "response_format": {"type": "json_object"}
}
```

Схема структуры запроса — [schemas/llm-request.schema.json](schemas/llm-request.schema.json). Байтовые ограничения, допустимое подмножество схем и частоту проверяет шлюз; JSON Schema не заменяет эти проверки.

## Формат и схема ответа

При `json_object` содержимое ответа — JSON-объект. При `json_schema` передайте:

```json
{
  "type": "json_schema",
  "json_schema": {
    "name": "buyer_requirements",
    "strict": true,
    "schema": {
      "type": "object",
      "properties": {"city_id": {"type": "string"}},
      "required": ["city_id"],
      "additionalProperties": false
    }
  }
}
```

Имя схемы содержит 1–64 латинских символа, цифры, `_` или `-`. Поддерживаются `type`, `properties`, `required`, `additionalProperties`, `items`, `enum`, `const`, `oneOf`, `anyOf`, `allOf`, числовые границы `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, ограничения `minLength`, `maxLength`, `minItems`, `maxItems`, а также `title` и `description`. В одном `enum` — до 100 значений, в одном списке альтернатив — от 1 до 8 схем. Допустимы объявления Draft 2020-12 и Draft-07 из примеров и контракта.

В схеме генерации не поддерживаются `uniqueItems`, `$ref`, `$defs`, `$id`, регулярные выражения и `format`. Для таких требований используйте `json_object` и проверяйте полученный объект в своём приложении. Основная схема конечного ответа помощника `schemas/response.schema.json` сохраняется целиком: ограничения на схему генерации её не отменяют.

API возвращает оболочку Chat Completions. JSON модели находится **строкой** в `choices[0].message.content`; разберите её отдельным JSON-парсером. В `usage` доступны входные и выходные токены. Пример оболочки — [llm/response.example.json](llm/response.example.json), схема — [schemas/llm-response.schema.json](schemas/llm-response.schema.json).

Промежуточную структуру для модели выбирает команда. Финальный ответ `run` должен соответствовать [основному контракту](CONTRACT.md). В сообщениях `run` используется `text`, в API модели — `content`.

## Ошибки и статистика

Ошибки шлюза имеют форму `{"error":{"code":"...","message":"...","request_id":"..."}}`. `request_id` может отсутствовать у ошибок чтения служебных методов.

| HTTP | Значение |
|---|---|
| 400 | Некорректные параметры, превышение входа/выходного предела или неподдерживаемая схема |
| 401 | Ключ отсутствует или неверен |
| 403 | Истёк срок, доступ отключён или недоступен; обратитесь к организатору |
| 413 | Полный запрос превышает 65 536 байт |
| 415 | Неверный `Content-Type` |
| 429 | Превышена частота/параллельность либо модель занята; учитывайте `Retry-After` |
| 502 | Сбой модели, незавершённая генерация `incomplete_output` или невалидный ответ `invalid_model_output` |
| 503 | Шлюз временно недоступен или не удалось сохранить состояние обращения |

Шлюз не повторяет генерации автоматически. При обрыве соединения результат исходного вызова может быть неизвестен; ограничивайте повторные попытки клиента. Для 429 выдерживайте паузу, а для 401/403 проверьте доступ с организатором. Ошибку сервиса нельзя превращать в `no_match`: используйте stderr и ненулевой код завершения по основному контракту.

`GET /v1/models`, `GET /v1/limits` и `GET /v1/usage` требуют тот же ключ. Они показывают модель, ограничения, имя команды, количество попыток и токены только вашей команды. `GET /health` — публичная проверка доступности. Частые вызовы статистики не нужны: достаточно обновлять её по необходимости.

Для `workers.dev` задавайте явный `User-Agent`. Стандартный `Python-urllib/3.12` может получить внешнюю ошибку `403 error code: 1010` до шлюза; такой ответ бывает обычным текстом. [Пример клиента](llm/client.py) передаёт имя приложения и обрабатывает ответ без JSON.

## Пример запуска

```sh
cp llm/.env.example .env
# Локально укажите индивидуальный ключ, полученный от организатора.
python3 llm/client.py --env-file .env --request llm/request.example.json
```

Клиент делает один вызов и не повторяет его автоматически. Он показывает протокол обращения к модели, а не готовое решение кейса. Рабочий ключ, `.env` и файлы с доступами не включайте в исходники, Git и публичные сообщения.
